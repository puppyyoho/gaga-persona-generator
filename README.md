# 嘎嘎人设生成器 v0.7.2

一个面向 SillyTavern 1.14.0+ 的世界观适配 User Persona 生成扩展。

嘎嘎人设生成器会读取当前角色卡和用户选择的世界书，调用 SillyTavern 当前连接的模型，生成新的 User Persona，或对当前已经启用的 Persona 进行保真优化。结果可直接复制到 Persona Description。只有用户主动勾选“参考当前开场白”时，扩展才会读取当前聊天的第一条角色开场白；不会读取后续聊天，也不需要额外填写 API Key。

## 当前版本功能

- “优化当前 U”完成后可在“优化后人设”和“修改对比”之间切换；新增、修改、删除与保留内容使用不同颜色，并显示修改前、修改后和简短原因。
- 修改记录随同一次优化请求返回，不额外调用模型，也不会进入复制内容、YAML 或自然语言人设；缺少结构化记录时自动使用本地文本差异。
- “参考当前开场白”会优先读取当前聊天正在显示的第一条角色开场白（包括已切换的备用开场白）；没有可用聊天开场白时，读取角色卡默认的第一条开场白，不会读取后续聊天。
- 修复选择“自定义字数”后被重置为“标准 1000 字”的问题，并记住上次填写的自定义字数。
- 每次打开面板和开始生成前都会重新读取当前连接、连接配置与模型；切换模型后不再沿用插件首次打开时的旧模型。
- 优化 U 和换一批名字会沿用同一个当前连接，连接管理器选中的配置会在配置仍与当前模型一致时优先使用；手动改过模型则以实时模型选择为准。
- 新版酒馆优先读取未经过 `generateRaw()` 清理的原始响应，避免正文被酒馆清理后误报 `No message generated`；只有思考、空响应、内容拦截和参数错误会分别给出对应提示。
- 开场白只作为场景证据，提示词会严格区分角色与 U、保守处理留白，并以角色卡、世界书和当前 U 原文中的硬事实为优先。
- 修复自定义栏目模板提示保存成功后，下拉列表仍为空且刷新后丢失的问题。
- 新增“优化当前 U”模式：读取当前 Persona Description，并结合角色卡与世界书改善自然度、因果联系、世界观适配度和长期扮演可用性。
- 优化模式会锁定当前 U 的姓名与明确事实，以保留原设定为首要目标；遇到世界观硬冲突时只做最小必要修正。
- 优化模式会自动勾选当前 Persona 绑定的世界书。切回新建模式后继续维持原有的身份隔离逻辑。
- 优化结果只显示在结果区，不会自动覆盖当前 Persona，确认后可自行复制粘贴。
- 支持保存自定义栏目模板：给当前勾选组合命名后即可长期保存、再次应用、更新或删除；模板不会改变性别、种族、篇幅等生成条件。
- 勾选身体或性爱栏目后，相关 Prompt 会启用更直白、有情色感的成人设定文风，可自然使用直接的器官与性行为词汇，同时避免把普通栏目无差别色情化。
- 修复当前已启用 User Persona 姓名污染新 Persona 的问题。
- 当前 Persona 绑定的世界书仍会被识别，但默认不勾选。
- 性别可选择随机、男、女或双性。
- 种族可选择随机、人类或人外；人外支持指定具体种族。
- 一次生成 3、5 或 7 个兼容同一人设的候选姓名。
- 点击候选姓名后，整份人设中的姓名与别名会同步切换。
- 支持“换一批名字”，不重新生成人设正文。
- 支持 YAML 与带小标题的自然语言两种输出格式，切换格式不重新调用模型。
- 支持精简、标准、详细、超详细和自定义字数（约 300–6000 字）。
- 选择的长度预设会立即同步目标字数；自定义字数留空时保留上一次有效值。
- 可选真流式输出：Chat Completion、Text Completion 或连接管理器支持时，模型生成期间边接收边显示，固定底栏同步显示字数与有效分片数。
- 流式失败会说明原因并回退普通生成，不会在生成结束后伪装成流式播放。
- 修复已选择但未实际使用的连接管理器配置抢占当前 SillyTavern API，以及目标字数被误当成 API 输出 token 上限而导致 422 的问题。
- Chat Completion 流式请求现在复用 SillyTavern 主聊天的原生参数构造路径与连接配置事件，不再把 `quiet` 请求强行改造成流式请求。
- 内置三维人物、既定处境、目标层级、行动回路、叙事身份、反应链、可信意外、关系地位、冰山取舍与发展接口等创作方法。
- 强制避免先否定后肯定的对照句式、破折号、统一栏目结构和模板化结论。
- 增加精简、标准、剧情丰富和自定义内容范围。
- “生成内容（可勾选）”现在会直接展开显示，不需要额外寻找折叠面板。
- 关系网络可选父母、兄弟姐妹、朋友、重要 NPC、前任、伴侣、竞争者和宠物。
- 身体设定与性爱设定可以逐项勾选，未选择的栏目不会进入 Prompt 或结果。
- 世界书预算会参考当前模型上下文大小动态收缩。
- 生成过程中提供停止按钮。
- 最近一次结构化人设、候选姓名、输出格式和选项会保存在扩展设置中。
- 悬浮入口支持桌面端与移动端拖动并记住位置；移动端使用更紧凑的圆形布局，尽量减少遮挡。
- 切换到更窄的屏幕时会自动修正已记忆的位置，避免悬浮入口跑到屏幕外。
- 移动端同样遵循“显示悬浮入口”开关；开启时会自动把入口放回屏幕内。
- 悬浮入口换成圆形嘎嘎图标，更适合拖动和快速识别。
- 悬浮入口支持在扩展设置中调整图标大小（40–120px），可一键恢复默认大小。
- 支持上传 PNG、JPG、GIF 或 WebP 作为自定义悬浮图标，也可以随时恢复默认图标；自定义图片只保存在当前酒馆设置中。
- 扩展设置里的打开按钮固定为横向胶囊样式，避免窄栏中逐字换行。

## 生成内容

默认“标准”预设包括：

- 基本身份
- 外貌与体型
- 性格与行为逻辑
- 成长经历
- 职业、经济与资源
- 能力与限制
- 生活习惯
- 与当前角色的关系

自定义模式还可以选择：

- 父母或监护人、兄弟姐妹、朋友、重要 NPC、前任、当前伴侣、敌人或竞争者、宠物
- 身高与体型、身体比例、胸部、生殖器、第二性征、疤痕与纹身、声音与动作习惯
- 性欲水平、性取向、性癖与偏好、主动或被动倾向、做爱时的反应、身体敏感点、节奏与氛围、禁区、事后互动

## 世界书识别

扩展会自动识别：

- 当前全局 World Info
- 角色主世界书
- 角色附加世界书
- 当前 Chat Lorebook
- 当前 Persona Lorebook
- 角色卡内嵌 Character Book

随机生成与定向生成中，为避免沿用当前 User 身份，Persona Lorebook 不会默认勾选，但仍可以在“世界书范围”中手动选择。优化当前 U 时，Persona Lorebook 会自动勾选，作为当前身份设定的一部分参与优化。

大型世界书会优先保留常驻和高顺序规则，并根据当前上下文预算截取。结果区会显示实际读取条目数。

## 安装

推荐在 SillyTavern 的 Extensions 面板中选择“安装扩展”，粘贴仓库地址：

    https://github.com/puppyyoho/gaga-persona-generator.git

也可以把整个文件夹放到当前用户扩展目录：

    SillyTavern/data/<你的用户>/extensions/persona-forge/

旧式全局扩展目录：

    SillyTavern/public/scripts/extensions/third-party/persona-forge/

安装后刷新 SillyTavern 页面。

## 使用

1. 进入某个角色聊天。
2. 在 Extensions 设置中打开嘎嘎人设生成器，或点击可拖动的悬浮按钮。
3. 选择随机生成、定向生成或优化当前 U。
4. 选择性别、种族、候选姓名数量和生成倾向。
5. 选择人设长度，或在“自定义字数”中填写目标字数。
6. 在“生成内容（可勾选）”中使用预设或逐项勾选想生成的内容。
   - 需要反复使用同一组栏目时，可以填写模板名称并点击“保存当前勾选”。
7. 确认世界书范围后点击“生成人设”或“优化当前 U”。
8. 从候选姓名中选择一个名字。
9. 选择 YAML 或自然语言格式。
10. 点击“一键复制”。

## 输出格式

YAML 模式适合结构化编辑、字段锁定和后续保存为 Persona。

自然语言模式使用“【基本身份】”“【外貌与体型】”等小标题，更适合直接阅读和粘贴。

两种格式使用同一份内部人设数据，因此切换格式不会重新生成，也不会产生额外模型请求。

## 流式说明

真正的实时输出要求模型服务、API 反向代理、SillyTavern 服务端与浏览器之间都持续转发 SSE 数据。生成时底栏会显示有效分片数；数量持续增加代表浏览器正在实时收到内容。插件会在连接管理器配置与实时模型一致时使用当前选中配置；如果用户刚在模型选择器里手动切换，则以实时模型选择为准。

如果最终提示“上游只返回了一个完整分片”，说明插件确实发出了流式请求，但模型服务或中间代理直到末尾才交付正文。浏览器无法提前展示尚未收到的数据，建议先用同一设备直接访问 SillyTavern 局域网地址测试，再检查隧道或反向代理是否开启了响应缓冲。

插件优先跟随 SillyTavern 当前正在使用的 API，并为结构化 JSON 预留与目标字数匹配的回复 token 空间。界面的“目标字数”仍然控制人物设定篇幅，同时会避免回复上限过低导致空响应。

Chat Completion 会使用与主聊天相同的 `normal` 流式参数构造路径，并触发 SillyTavern 的连接设置就绪事件，让代理、连接管理器和模型专用字段有机会完成最后调整。

如果流式连接仍被上游拒绝，错误提示会同时显示实际 API 来源与模型名称，便于区分代理限制和模型参数问题。

## 兼容说明

从 v0.7.0 起，最低支持 SillyTavern 1.14.0。插件会在启动时检测宿主实际提供的接口，新版继续使用完整实现；1.14–1.17 缺少某项新版接口时自动进入兼容路径，不会修改用户当前的生成预设。

- 普通生成优先使用新版 `generateRawData()` 读取原始响应；缺失该接口时使用 `generateRaw()`，再回退到 `generateQuietPrompt()`。
- 1.14–1.17 没有新版 Chat Completion 参数构造器时，会从当前连接设置构造等价的流式请求。
- 旧版 Text Completion 忽略流式覆盖参数时，兼容层会显式补回 `prompt` 与 `stream`。
- `getWorldInfoNames()` 不存在时，继续从 `world-info.js` 的公开运行时数据识别世界书。
- 宿主缺失的能力会在插件顶部提示；其余可用功能不会被连带关闭。

主要公开调用来自 SillyTavern.getContext()：

- generateRaw()
- ChatCompletionService / TextCompletionService（用于当前 API 的流式生成）
- ConnectionManagerRequestService（可选，用于连接管理器配置的流式生成）
- loadWorldInfo()
- getWorldInfoNames()
- extensionSettings
- name1 / powerUserSettings.persona_description（只读当前 Persona 姓名与描述）
- chat[0].mes（仅在用户勾选时读取当前聊天正在显示的第一条角色开场白）
- characters[characterId].first_mes（当前聊天没有可用开场白时的默认回退）
- eventSource / eventTypes
- stopGeneration()

宿主访问与降级逻辑集中在 `st-compat.js`，新版功能路径和旧版回退路径互不覆盖。

为了识别全局启用和角色附加世界书，扩展还会只读动态导入 world-info.js 中的 selected_world_info 与 world_info.charLore。导入失败时会自动降级。
